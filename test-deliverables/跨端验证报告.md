## 四、关键业务逻辑一致性检查

### 4.1 "长得像但其实并不一样" 的业务逻辑

| 检查项 | 状态 | 详情 |
|--------|------|------|
| JWT payload 字段名一致性 | ✅ 一致 | 统一使用 `sub` + `role`，家长用 `type='parent'` 映射 |
| 分页字段一致性 | ✅ 一致 | 后端统一 `skip/take`，前端 `web-app` axios 适配，小程序 `request.js` 自动解包 `items` |
| 学号跨校歧义处理 | ✅ 已处理 | `auth.service.ts:45-49` `findStudentByNoForLogin()` 优先返回已开启家长登录的记录 |
| 家长登录 401 消息区分 | ⚠️ 风险 | `request.js:119` 正则 `/登录已过期\|未登录\|缺少令牌\|账号已禁用.../` 可能遗漏新的错误文案 |
| 教师 user 字段映射 | ✅ 一致 | `auth.service.ts:113-212` 返回 `subject/subjects/position/avatar` 字段；`auth.ts` 正确映射 |
| 登录响应双角色 | ⚠️ 风险 | `auth.controller.ts` 返回 `needsRoleChoice: true` + 双 token；Web `auth.ts:169` 处理，但小程序端处理未见完整代码 |
| HTTP 方法一致性 | ✅ 一致 | Web `PUT/PATCH` 区分明确；小程序 `request.js:156-159` 同名方法对应相同方法 |

### 4.2 返回码一致性

| 场景 | Web 处理 | 小程序处理 | 状态 |
|------|---------|-----------|------|

## 七、风险与建议

| 风险项 | 严重度 | 建议 |
|--------|--------|------|
| 小游戏得分无持久化 | 🔴 高 | 新增 `/api/game-scores` 后端接口，前端得分后上报 |
