## 4. 缺陷清单

### P1-MSG-01：教师→家长站内信不可达（跨端契约断裂）— ✅ 已修复
- **严重级别**：P1（核心家校沟通功能不可用）
- **复现用例**：MSG-08、MSG-08b
- **现象（修复前）**：
  1. 教师发送站内信给家长：`recipientId = ${studentId}_${parentName}`（如 `9d75f83f-..._张小明家长`），`recipientRole = 'parent'`，创建成功 201。
  2. 家长端收件箱 `GET /api/messages`：`items=0`，永远看不到该消息。
  3. 家长标记已读 `PATCH /api/messages/:id/read`：404「消息不存在或您无权操作」。
- **根因**：`server/src/messages/message.service.ts` 的 `listRecipients` 用 `${studentId}_${parentName}` 构造家长账号 id；而家长登录 JWT 的 `sub` 由 `server/src/im/parent-im.util.ts` 的 `parentImUserId()` 稳定派生（`p_` + hash(studentId|relation|parentName)）。两者不一致 → `MessageService.list/markRead/unreadCount/remove` 以 `recipientId = JWT.sub` 匹配时永远匹配不上。
- **修复**（`server/src/messages/message.service.ts`）：
  - `listRecipients` 中家长账号 id 改用 `parentImUserId({ studentId, relation: '家长', parentName: parentName || '家长' })` 派生，与家长登录 JWT sub 的生成算法**完全一致**（relation 固定 `'家长'`，与登录侧相同）。
  - 前端（Web `MessageBoard.vue` / 小程序 `messages.vue`）透传 recipientId，无需改动。
- **复测结果**（`qa/verify-msg-fix.mjs`，11/11 通过）：
  1. ✅ 教师收件人列表返回家长账号（6 个，id 均为 `p_` 前缀）
  2. ✅ 收件人列表 id 与家长 JWT sub 完全一致（`sub=p_13hgsat` 精确匹配）
  3. ✅ 教师发送消息创建成功（201）
  4. ✅ **家长收件箱能看到教师消息**（修复前 items=0）
  5. ✅ 家长标记已读成功（修复前 404）
  6. ✅ 家长未读数归零
  7. ✅ 家长删除消息成功
  8. ✅ 家长→教师回信成功且教师收件箱可见（双向打通）
- **回归确认**：修复后全量重跑 v1（75/75）+ v2（81/81），全部通过，无回归。

### P2-ENV-01：better-sqlite3 并发写锁环境噪声（无需修复）
- **现象**：并发 20 写场景（notes 创建 / dashboard）压测 avg 25~34s；单次调用 4~90ms 正常。
- **根因**：SQLite 单写者模型 + WAL checkpoint 全局阻塞，仅影响内存库测试环境；生产 MySQL + 异步驱动无此问题。
- **处置**：已记录，待生产 MySQL 环境复测写场景 RPS。
