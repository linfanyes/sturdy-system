## 四、发现并修复的缺陷

### 4.1 已修复的代码缺陷

| 缺陷 ID | 严重等级 | 描述 | 修复方式 |
|---------|---------|------|---------|
| BUG-001 | P1 | `/api/auth/me` 不返回教师 subject 信息 | 在 `auth.service.ts` 的 `me()` 方法中增加教师用户信息查询，返回 subject/subjects 字段 |
| BUG-002 | P1 | 班级创建使用硬编码的教师 ID，导致"指定的班主任不在本校"错误 | 改为从 API 获取真实教师 ID |
| BUG-003 | P1 | 考试创建缺少必填 `term` 字段 | 在请求体中增加 `term: '2026春季'` |
| BUG-004 | P2 | 前端 API 代理指向云托管地址 | 修改 `vite.config.ts` 代理目标为 `localhost:3000` |
| BUG-005 | P2 | 前端运行时配置覆盖本地代理 | 注释 `config.js` 中的 `API_BASE_URL` |

### 4.2 测试脚本改进

| 改进项 | 描述 |
|--------|------|
| 响应解析 | 修复 `items` 数组解析，兼容 `{ items: [...] }` 格式 |
| 数据隔离 | 密码重置测试后恢复原密码，避免污染后续测试 |
| 速率限制 | 增加管理员重新启用逻辑，防止禁用状态影响登录测试 |
| 执行顺序 | 调整成绩列表测试在创建之后执行 |
| 动态 ID | 班级/考试创建使用 API 获取的真实 ID 而非硬编码 |

1. **后端 API**: 55 用例全部通过，覆盖认证、权限隔离、CRUD、数据完整性等核心场景
2. **Web 前端**: 三类角色（超级管理员、学校管理员、教师）登录、导航、菜单过滤均正常
3. **权限控制**: 四级角色隔离正确，教师无法访问管理员接口，学校间数据隔离生效
4. **修复缺陷**: 共发现并修复 5 个缺陷（3 个代码缺陷、2 个配置缺陷）
5. **系统稳定性**: 速率限制、审计日志、健康检查均正常工作
