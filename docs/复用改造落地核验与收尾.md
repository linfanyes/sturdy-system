## 二、剩余缺口清单（精确到文件行号）

### 缺口 1：SSE 流式解析 —— web-app 两处手写实现未用 `createSSEParser`

**为什么重要**：`createSSEParser` 按 `\n\n` 分隔完整 SSE event、内部维护跨 chunk 缓冲，能正确处理「一个事件被网络分片拆到两次 read()」的情况。而 web-app 现有手写实现用 `buf.split('\n')` + 逐行处理，**无法处理跨 chunk 断行**——AI 流式回答较长、网络分片多时可能截断/漏字。

- **1a. `web-app/src/views/ai/AiChat.vue:140-167`**
  - 手写 `getReader` + `split('\n')` + `data: ` 前缀 + `[DONE]` + `JSON.parse`。
  - 内置 401 清除逻辑（141-145），绕过了 `request.ts` 拦截器。
  - 收尾：改为用 `createSSEParser({ onDelta, onError, onDone })`，只保留 transport 层（reader + TextDecoder），协议解析交给 shared；401 处理抽到统一函数（见缺口 2）。
- **1b. `web-app/src/api/teacher.ts:522-551`**
  - 虽用了 `parseSSELn`（共享行解析），但仍是手写 `split('\n')` 循环，无法跨 chunk 断行。
  - 收尾：改用 `createSSEParser`，把 onDelta/onError 传入，去掉手写循环。

**收益**：三端（web AiChat、web teacher.ts、mini request.js `streamChat`）AI 流式协议解析收敛到 shared 同一份实现，消除三套解析差异与跨 chunk bug。

### 缺口 2：web-app 两处内联 401 处理（随缺口 1 一并解决）

- `web-app/src/views/ai/AiChat.vue:141-145`、`web-app/src/api/teacher.ts:522-526` 各自内联「清 token + 跳登录」，与 `web-app/src/api/request.ts` 拦截器逻辑重复。
- 收尾：在 `request.ts`（或 shared）暴露统一 `handleUnauthorized()`，两处直接调用，消除三份重复。

### 缺口 3：安全 JSON 解析 `safeParse` 未全量复用

`shared/utils/general` 已有 `safeParse`（try/catch + JSON.parse），但以下页面仍各自手写：

- **web-app**：`src/views/exams/DataDashboard.vue:75-79`（手写 safeParse）。
- **mini-program**：`src/pages/students/students.vue:704`、`src/pages/class-activities.vue:82`、`src/pages/ai/ai-interactive.vue:107`、`src/pages/school-admin/school-admin.vue:782`。
  - mini 端已有 `src/common/util.js:3` re-export shared `safeParse`，直接改引即可。

**收益**：统一解析错误兜底行为，避免各页 try/catch 差异。

### 缺口 4：日期格式化散点

- `web-app/src/views/office/TeachingCalendar.vue:58` 手写 `YYYY-MM-DD`，可换 shared `formatDateTime`。
- `web-app/src/views_deprecated/.../Notes.vue:61-62` 手写相对时间（**已弃用目录，可忽略，低优先**）。

### 保持不动（非缺口）

- `web-app` 其他游戏（Tetris / Dice / Flappy 等）在 shared/games 无对应版本，属端私有，**保持内联**（无需为它们新建 shared 状态机，除非后续要跨端对齐）。
- 各端平台适配层（存盘/打开文件、Canvas/DOM 渲染、wx.cloud 调用）本就是 adapter，不应上移 shared。

## 四、建议的后续演进（超出本次收尾范围）

若希望把复用改造进一步推进到「schema 驱动」的完整收益，可作为独立的下一阶段：

1. **Web schema-driven 渲染器全量落地**：目前 `SchemaCrudPage.vue` 已局部采用，可将剩余手工 CRUD view（如班级、学生、成绩等）逐步切换，目标是手工 view 减少 60%+。
2. **AI 对话历史跨端行为统一**：确认 `web-app/src/api/chat.ts` 与 `mini-program/src/common/chat-history.js` 的会话 DTO 是否已完全对齐 shared/api/endpoints。
3. **统一 401 处理下沉到 shared**：当前三端 401 策略在拦截器层各自实现，可评估是否抽为 shared/auth 的 `sessionInvalidHandler` 契约。

这些建议均需先确认范围与验收口径，再单独立项。

## 五、风险与回滚

- 收尾动作均为**文件级局部替换**，不改 shared 接口与运行行为；每步 `tsc --noEmit` + 相关页面回归。
- `AiChat.vue` / `teacher.ts` 的 SSE 改造涉及流式协议，需在**真实 AI 接口**上验证长回复不断行，建议保留改造前后对比。
- 回滚：每步独立 commit，可单独 revert。
