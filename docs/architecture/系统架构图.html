1 · 部署与网络拓扑

同一后端、两种入网方式：Web 走公网 HTTPS，小程序走微信云托管私有链路（免域名/备案）。

Web 公网入口 小程序私有链路 云托管容器 云数据库

2 · 后端分层架构

NestJS 模块经全局 Guard/Pipe 进入；绝大多数业务模块继承 CRUD 工厂基类，以 teacherId 为租户键实现隔离。

3 · 双前端架构对照

Web 与小程序在框架、路由、状态、传输、图表上各异，但共享同一后端与 @gardener/shared 基线。

4 · 核心数据流

四类关键流程：统一登录鉴权、微信家长登录、考试与成绩分析、家校通知推送。

① 统一登录与鉴权

  1. 前端 POST /auth/unified-login
  2. 后端 超管→校管→教师→家长 瀑布命中
  3. bcrypt 比对密码 → 签发 JWT(role/schoolId)
  4. GET /auth/me 拉取 profile + effectiveFeatures
  5. 后续请求带 Bearer；Guard 强制校验（401 清态闭环）

② 微信家长登录（仅家长）

  1. wx.login() → code
  2. POST /auth/wechat-login
  3. code2Session() → openid
  4. 仅查 Parent.openId + 解析 kids
  5. 命中签发家长 token+kids；未命中返回 needsBind

③ 考试与成绩分析

  1. POST /exams（建考试，含 subjectFullScores）
  2. POST /grades（按科目写全班分数数组）
  3. 分析端点聚合：trend/rank/weak/student
  4. 服务端按 classId/teacherId 隔离计算

④ 家校通知推送

  1. 教师 POST /notices（scope=class|school）
  2. 触发 SecurityService.pushNotice()
  3. 取 access_token → message/subscribe/send
  4. 逐个家长下发（单条失败不中断）
跨端一致性机制：前端守卫仅做 UX，真实权限由后端 @Roles+JWT(t.sub)+@Feature 强制校验；业务规则/学科/职务统一来自 @gardener/shared；数据按 teacherId/classId/studentId 隔离。
