## 1. 文档概述

本文档基于仓库源码的实际扫描结果（非 PRD 假设）编写，目标是为「园丁工作台（Gardener Workbench）」这一 K12 校园管理工作台提供**权威的架构基线**：说明系统定位、技术栈、部署拓扑、**核心模块划分**与**关键数据流**，并附带一份从源码中发掘的技术债清单，供后续重构与评审参考。

> ⚠️ 与若干既有文档的偏差已在正文及第 10 节标注：本项目**无 Swagger**、**未使用 Redis**（限流为进程内存）、JWT 为**手写实现（非 passport）**、`shared/dist` **实际未构建**且后端源码**零引用** shared。

## 2. 系统定位与总览

园丁工作台是一个面向 K12 学校的多角色协同管理平台，覆盖 **超管（平台）→ 校管（学校）→ 教师 → 家长/学生** 四级用户，提供班级管理、教学主数据、考试与成绩、学生评价与成长、班务运营、家校沟通、教师办公与 AI 备课等能力。

| 维度 | 现状 |
|------|------|
| 角色模型 | `super`（平台超管）、`school_admin`（校管）、`teacher`（教师）、`parent`（家长，含学生视图） |
| 客户端 | Web SPA（Vue3）、微信小程序（uni-app）、管理后台（静态资源，随服务端托管） |
| 后端 | 单仓库 Monorepo：NestJS + TypeORM + MySQL，部署于腾讯云「云托管」容器 |
| 共享层 | `@gardener/shared`（常量/类型/校验器单一事实来源，三端复用） |
| 业务规模 | 45 个 NestJS 模块、56 个实体类、173 条 Web 路由、160+ 小程序页面 |

## 4. 部署架构与网络拓扑

系统采用**同一后端、两种入网方式**的部署形态，核心区别在于 Web 与小程序到达 NestJS 容器的网络路径不同。

```
┌─────────────────────┐         HTTPS 公网          ┌──────────────────────────────┐
│  Web 端 (Vue3 SPA)   │ ──────────────────────────► │  微信云托管服务 tec-work        │
│  web-app (Vite)      │   https://tec-work-*.       │  (容器 :3000, NestJS)          │
│  public/config.js    │   sh.run.tcloudbase.com/api │  ├─ setGlobalPrefix('api')     │
└─────────────────────┘                             │  ├─ runMigrations() 启动自检    │
                                                    │  └─ app.listen(3000,'0.0.0.0')  │
┌─────────────────────┐   微信私有链路 (免域名/备案)  │          │                     │
│ 小程序 (uni-app)     │ ──────────────────────────► │          ▼                     │
│ wx.cloud.callContainer│  env + X-WX-SERVICE:tec-work│  腾讯云数据库 MySQL 8 (VPC)    │
│  config.js           │                             └──────────────────────────────┘
└─────────────────────┘
```

**两条入网路径：**

1. **Web 端（公网 HTTPS）**：`web-app/public/config.js` 中的运行时变量 `window.__APP_CONFIG__.API_BASE_URL` 指向云托管公网域名 `https://tec-work-283329-8-1440166408.sh.run.tcloudbase.com/api`。本地开发时由 Vite 代理 `/api → http://localhost:3000` 回落。
2. **小程序端（私有链路）**：`mini-program/src/common/config.js` 定义 `CLOUDRUN_ENV` / `CLOUDRUN_SERVICE='tec-work'`，通过 `wx.cloud.callContainer`（带 `X-WX-SERVICE` 头）在微信私有网络内转发到同一容器。**无需公网域名、无需登记 request 合法域名、免公网流量与 ICP 备案**。

**关键支撑组件：**
- 后端 `main.ts`：`CORS` 为 **fail-closed**（未配置 `CORS_ORIGIN` 默认禁止跨域；生产环境 `*` 直接抛错拒绝启动）；请求体上限放宽至 5MB（AI 大上下文）；`runMigrations()` 在启动时执行 `server/migrations/*.sql`；生产环境对 `JWT_SECRET` / 超管默认口令做硬性自检。
- 容器化：`server/Dockerfile` 三阶段 `node:20-alpine`，仅 COPY `server/` 自身（**不含 `../shared`**，与「后端零引用 shared」自洽），`USER node` 非 root，`EXPOSE 3000`。
- 配置双层：基础设施走 `.env`（`ConfigModule`）；业务运行时配置（微信 AppSecret、IM 密钥、AI Key）存 `app_config` 表键值库，可由超管后台改、`.env` 仅作种子/兜底。

## 5. 后端架构

### 5.1 启动与全局机制

`bootstrap()`（`server/src/main.ts`）顺序：创建 app → 放宽 body 上限 → CORS → `setGlobalPrefix('api')` → 全局 `ValidationPipe`（whitelist+transform）→ 全局 `TypeOrmExceptionFilter` → 静态托管 `web-app/dist` → 生产自检 → `runMigrations()` → `listen(0.0.0.0)`。

全局守卫/管道：
- `ThrottlerModule`（内存存储，`60/分钟`默认），`APP_GUARD` 全局注册。
- `JwtAuthGuard`：手写 `CanActivate`，解析 `Authorization: Bearer`，角色归一化（家长令牌用 `type` 字段），与 `@Roles` 元数据比对。
- `FeatureGuard`：功能包第二维授权，须与 `JwtAuthGuard` 组合使用。

> 注意：并发说明中「Redis 限流」**并不存在**——限流为进程内存，云托管横向扩容后配额按实例倍增（见第 10 节）。

### 5.2 模块地图（45 个模块）

绝大多数模块把 `service + controller`（有时含 `entity`）内联在 `*.module.ts` 单文件中，并继承通用 CRUD 基类。按业务域分组：

| 域 | 模块（路由前缀） | 核心实体 |
|----|------------------|---------|
| **平台/认证** | `auth`(/auth)、`users`(/users)、`config`+`ai-providers`(/config,/ai-providers)、`ai`(/ai)、`admin`(/admin)、`school-admin`(/school-admin)、`parent-auth`(/parent-auth)、`security`(/security)、`audit`(无控制器)、`feature`(全局) | User、SchoolAdmin、Parent、AppConfig、AiSettings、AiProvider、AuditLog |
| **教学主数据** | `classes`(/classes)、`students`(/students)、`teachers`(/teachers)、`school`(/schedules,/attendances,/homework,/notices,/resources)、`exams`(/exams)、`grades`(/grades)、`semesters`(/semesters)、`seats`(/seat-layouts) | ClassItem、Student、Teacher、ScheduleItem、Attendance、Homework、Notice、Resource、Exam、Grade、SeatLayout |
| **学生评价/成长** | `engagement`(/reward-records,/score-records,/group-scores)、`award`(/award-records,/award-categories)、`growth`(/growth-entries,/behavior-records)、`checkin`(/checkins)、`reading-log`(/reading-logs) | RewardRecord、ScoreRecord、GroupScore、AwardRecord、AwardCategory、GrowthEntry、BehaviorRecord、Checkin、ReadingLog |
| **班务运营** | `class-ops`(/class-expenses,/class-activities,/class-duty-configs)、`duty-roster`(/duty-rosters)、`gallery`(/class-galleries,/my-galleries) | ClassExpense、ClassActivity、ClassDutyConfig、DutyRoster、ClassGallery、MyGallery |
| **家校沟通** | `parent-contact`(/parent-contacts,/notice-templates)、`home-visit`(/home-visits)、`im`(/im)、`messages`(/messages)、`notification`(/notifications)、`student-info-update`(/student-info-updates) | ParentContact、NoticeTemplate、HomeVisit、Message、NotificationItem、StudentInfoUpdate |
| **教师办公/AI** | `generated`(/generated/*)、`notes`(/notes,/todos,/picker-history)、`work-log`(/work-logs)、`lesson-observation`(/lesson-observations)、`teaching-calendar`(/teaching-calendar)、`backup`(/backups) | GeneratedPaper/LessonPlan/Knowledge、NoteItem、TodoItem、WorkLog、LessonObservation、TeachingCalendarItem、BackupSnapshot |
| **资源库/教材** | `textbook`(/textbooks,/school-admin/textbooks)、`resource-library`(/resource-library,/school-admin/resource-library) | Textbook→TextbookUnit→TextbookKnowledgePoint（三层树）、Poem、MathFormula、EnglishWord |

### 5.3 认证与授权

**JWT 策略（手写，非 passport）**：Bearer 令牌 → `jwt.verify` → 角色归一化 → `req.user` → `@Roles` 比对。

**四类角色：**

| role | 来源 | 令牌 payload |
|------|------|--------------|
| `super` | `.env` 的 `SUPER_ADMIN_USER/PASSWORD` 硬比对（不入库） | `{sub:'super', role:'super'}` |
| `school_admin` | `school_admins` 表 | `{sub, role, schoolId}` |
| `teacher` | `users` 表 | `{sub, role:'teacher', schoolId}` |
| `parent` | `parents`/`students` 表 | `{sub: imUserId, type:'parent', parentId, studentId, ...}` |

**统一登录（4 级瀑布）**：`AuthService.unifiedLogin()` 按 超管 → 校管 → 教师 → 家长 顺序命中用户名即锁定分支（密码错误明确报「密码错误」，配合限流防枚举）。教师若同时有 `parentId` 且存在 `Parent` 记录，返回 `{needsRoleChoice, roles:['teacher','parent'], ...}` 并签发双令牌（师兼家）。

**微信登录（仅家长）**：`WechatService.code2Session()` 调 `sns/jscode2session`；命中 `Parent.openId` 后签发家长令牌 + `kids[]`；教师即使已绑定 openid 也**必须用账号密码登录**（规避身份歧义）。

**租户/学校隔离（三层叠加）：**
1. `teacherId` 租户键（`BaseEntity.teacherId`，全系统绝大多数实体继承）；
2. 班级协作层（`ClassMemberService`，`class_members` 唯一索引 `teacherId+classId+term`）；
3. `schoolId`（校管/超管域过滤）。

**功能包（Feature Flags，第二维授权）**：`@Feature(keys)` + `FeatureGuard`，`FEATURE_FLAGS` 共 35~40 个 key（与 `shared/constants` 同源副本）。`FeatureService.getEffectiveFeatures()`：超管/校管返回全集；教师/家长取「学校级 ∩ 教师级」交集（某级为 null/[] 视为全集）。管理端点刻意不标 `@Feature` 以避免语义歧义。

### 5.4 CRUD 工厂与租户隔离核心

理解全系统的钥匙是三件套基类：

- **`CrudController<T>`**：`@Roles + @UseGuards(JwtAuthGuard)`，提供标准 create/findAll/findOne/update/remove；`stripUnsafe()` 剔除 `UNSAFE_KEYS = {teacherId,id,role,createdAt,updatedAt,isDeleted}` 防批量赋值越权（mass assignment）；`MAX_TAKE=500` 分页截断。
- **`CrudService<T>`**：三种查询模式——指定 `classId` 经 `canAccess()` 校验；班级维度实体未指定 classId 时取可访问班级集合 `In(classIds)`；默认 `where.teacherId` 严格隔离。可覆写 `isClassScopedEntity()` 开启「同班协作」。
- **`BaseEntity`**：`id(uuid)` + `teacherId`(租户键) + `createdAt/updatedAt`。

### 5.5 横切关注点

- **AI 代理（可插拔 OpenAI 兼容协议）**：`ai_providers` 表（超管维护全局清单）+ `ai_settings` 表（每教师自存 apiKey，**密钥绝不下发小程序**）；默认 `dashscope` 兼容端点。路由含 `/ai/chat`（SSE 流式）、`chat-sync`、`parse`、`gen-image/视频`、`asr/ocr`、`analyze-exam`、`diagnose`。安全加固：`maxRedirects=0` 防 SSRF、`MAX_FILE_BYTES=10MB`、`magic bytes` 校验真实类型。
- **文件解析矩阵**：`.xlsx`→exceljs、`.docx`→mammoth、PDF→pdfjs-dist（扫描版经 `@napi-rs/canvas` 光栅化后 OCR）。exceljs 替换 SheetJS 是为规避 CVE-2023-30533 / CVE-2024-22363。
- **微信消息安全与推送**：`SecurityService` 唯一管理 access_token（`msgSecCheck`/`imgSecCheck`/`sendSubscribe`）。⚠️ 订阅消息模板 ID 仍为占位符 `'NOTICE_TEMPLATE_ID'/'HOMEWORK_TEMPLATE_ID'`。
- **腾讯云 IM**：`ImService.getUserSig()` 服务端 HMAC-SHA256 签名（7 天有效期）；`parentImUserId()` 派生稳定 IM 账号，同时被用作家长 JWT 的 `sub`。
- **审计 / 备份 / 异常**：`AuditService.log()`（静默失败不阻塞）；`BackupSnapshot`（手动/自动快照）；`TypeOrmExceptionFilter` 统一 `{statusCode,code,message}`，DB 错误映射为 `DB_ERROR` 不暴露 SQL。

### 5.6 数据模型总览（关键观察）

- **全库零 `@ManyToOne/@OneToMany/@JoinColumn` 关系装饰器**：所有关联为裸 `xxxId: string` 列 + 应用层手动 join（`In(ids)` + Map 拼装）。无数据库外键约束——刻意的反范式/弱耦合设计，配合 `synchronize` 与 SQL 迁移。
- **成绩为反范式存储**：`Grade` 表按「科目一行、内嵌全班分数数组 `scores: GradeScore[]`」存储，非一生一行。
- **`teacherId` 是全系统租户键**；资源库/教材类表（`Textbook*`、`Poem` 等）按 `schoolId` 隔离而非 `teacherId`。
- 枚举均为字符串字面量 + 注释（无 TS `enum`、无 `@Column({type:'enum'})`）。

## 6. 前端架构

### 6.1 Web 端（`web-app`）

- **目录**：`api/`（10 个 TS，单一 axios 实例 + 拦截器）、`components/`、`composables/`、`config/`、`constants/`、`layouts/`、`router/`、`stores/`（仅 `auth`、`roleSwitch`）、`views/`（166 个 .vue，13 个业务子目录）。
- **路由**：`createWebHashHistory`，173 条 path，按角色分组（`/super`、`/school-admin`、`/teacher`≈145 条、`/parent`）。`router.beforeEach` 四道判定：登录态 → roles → feature → 已登录访问 login 重定向。
- **状态**：Pinia `useAuthStore`（token/user 持久化 localStorage，`fetchMe()` 合并 `effectiveFeatures`）、`useRoleSwitchStore`（师兼家双身份内存态）。
- **API 层**：`request.ts` 是单一 axios 实例；baseURL 解析链 = `运行时 config.js > 构建期 VITE_API_BASE > 兜底 /api`；请求拦截注入 Bearer，响应拦截统一解包，**401 时清态并 `location.hash='#/login'` 形成闭环**。
- **图表**：自写 SVG 组件（SvgBar/Line/Pie/Progress），无图表库。
- **shared 消费**：`file:../shared` 声明 + Vite alias 直连源码 + `vendor-shared` 独立分包。

### 6.2 小程序端（`mini-program`）

- **目录**：`pages.json`（105 主包 + 3 分包 `games/tools/ai` + tabBar 5 项）、`common/`（14 个 .js + `mock/`）、`components/`、`pages/`（160 个 .vue）。
- **请求层（云托管私有链路）**：`common/request.js` 封装 `wx.cloud.callContainer`，带 `config.env` + `header['X-WX-SERVICE']`，显式 30s 超时保护；`api.get/post/...`、`parentApi`（家长令牌隔离）、`streamChat`（SSE 流式，手写 `ab2str` UTF-8 解码）。超管/校管页另建本地 `apiCall` 形成第二套实现。
- **状态**：Vue3 `reactive()` 单例（`auth/theme/parent/mockMode`），`uni.setStorageSync` 持久化——**无 Pinia/Vuex**。
- **守卫**：`route-guard.js` 用 `uni.addInterceptor` 拦截 4 个导航方法（token 推角色 → `PAGE_ROLES` → `FEATURE_PATH_MAP`）。
- **Schema 驱动**：`crud-schema.js` 用 28 实体配置驱动 `pages/crud/crud.vue` 动态生成全量管理页；`subject-schema` / `quicktool-schema` 驱动 AI 工具表单。
- **图表**：`@qiun/ucharts`。**演示模式**：`common/mock/` 提供 7 个 endpoint 域，`DEMO_MODE_ENABLED` 按 `NODE_ENV` 在生产隔离。

## 7. 共享包 `@gardener/shared`

`shared/{constants,types,validators}/index.ts`（源码平铺，无 `src/`），通过 `tsconfig paths` 被三端直连源码消费，是**常量/类型/校验器的单一事实来源**。

- **常量**：`SUBJECT_OPTIONS`（15 门）、`GRADE_OPTIONS`、`ROLE_OPTIONS`、`ALL_POSITIONS`（27）、`FEATURE_FLAGS`（40）、`SCHEMES`/`FONT_SIZES`、`PHONE_REGEX`、`CLASS_NAMING_RULE`。
- **类型**：`User/Teacher/Student/Class` + `ApiResponse/PageParams/PageResult/JwtPayload/LoginCredentials`（**仅 4 个实体类型**，Parent/Exam/Score/H... 未提升为共享类型）。
- **校验器**：`isPhone/isValidPhone`、`validateClassName/generateClassName/parseClassName`、`isSubject`、`hasFeature`（空数组=fail-open 全放行）、`isGrade/isScore/isStudentNo/clip` 等。

> ⚠️ 关键事实：后端 `src/**` **零引用** shared（仅集成测试用到），`shared/dist` 实际未构建，`package.json` 的 `exports` 指向不存在的 `dist`。当前完整形态依赖各端 alias 直连源码（即「方案 C」）。详见第 10 节。

## 8. 核心数据流

### 8.1 统一登录与鉴权流

```
浏览器/小程序 → POST /auth/unified-login {username,password}
  → AuthService.unifiedLogin()：超管→校管→教师→家长 瀑布命中
  → 命中分支后密码比对（bcrypt） → 签发 JWT（写入 role/schoolId）
  → 前端存储 token → GET /auth/me 拉取 profile + effectiveFeatures
  → 之后每个请求带 Bearer，JwtAuthGuard + FeatureGuard 强制校验
```

### 8.2 微信家长登录流

```
小程序 wx.login() → code → POST /auth/wechat-login {code}
  → WechatService.code2Session() → openid
  → 仅查 Parent.openId（+ StudentParentService 解析 kids）
  → 命中签发家长 token + kids[]；未命中返回 {needsBind, openid}
```

> 教师**不支持**微信登录（`bindWechatTeacher()` 永远抛错）——规避师兼家身份歧义。

### 8.3 考试与成绩上报/分析流

```
校管/教师 POST /exams（建考试，含 subjectFullScores）
  → 教师 POST /grades（按科目写入：Grade.scores = 全班学生分数数组）
  → 分析端点：/grades/analysis/exam|trend|rank|student/:id|weak
       （服务端按 classId/teacherId 隔离聚合，返回趋势/排名/薄弱点）
```

### 8.4 家校通知推送流

```
教师 POST /notices（建公告，scope=class|school）
  → 触发 SecurityService.pushNotice()
  → 经 access_token 调 /cgi-bin/message/subscribe/send
  → 逐个家长下发订阅消息（单条失败不中断）
```

### 8.5 跨端一致性机制

- **共享基线**：`shared/constants`（FEATURE_FLAGS、学科、职务）与 `shared/validators`（手机号、班级命名）在三端复用，保证业务规则一致。
- **权限边界**：前端守卫仅做 UX 跳转/菜单显隐；**真实权限由后端 `@Roles` + JWT(`t.sub`) + `@Feature` 强制校验**，401 触发前端清态闭环。
- **数据隔离**：所有家长数据面按 `studentId`/`classId`/`teacherId` 隔离，禁止越权查看。
- **功能包解析公式**：effective = 学校级 ∩ 教师级（某级 null/[]=全集），在后端、Web `api/feature.ts`、小程序 `common/feature.js` **三处各实现一份**（尚未收敛进 shared）。

## 9. 关键设计决策与权衡

1. **反范式数据模型 + 应用层 join**：无外键、无关系装饰器，换取云托管 `synchronize` 与弱耦合弹性，代价是跨实体一致性靠业务代码保证。
2. **CRUD 工厂基类**：45 模块大量内联单文件 + 继承基类，换来极低样板成本，代价是模块边界模糊、路由/实体偶发重复注册。
3. **手写 JWT / 内存限流**：减少依赖（无 passport/redis），代价是横向扩容限流失效、需自行维护安全逻辑。
4. **双入网拓扑（公网 + 私有链路）**：小程序免域名/备案/公网流量，代价是两端请求封装各自一套、维护成本翻倍。
5. **shared 走源码 alias 而非构建发布**：零发布流程、改动即时生效，代价是 `dist` 与 `package.json exports` 名存实亡、类型检查路径有 bug。
