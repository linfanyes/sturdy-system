# 密码管理系统修复报告

## 问题清单与根因分析

### 问题1：Web端教师用户登录提示密码错误，重置密码后仍无法登录

**根因**：Web端「编辑教师」弹窗中有密码输入框，管理员填写新密码点击保存后，前端将 `password` 字段发送到 `updateTeacher` API，但后端 `updateTeacher` 的 DTO **没有接受 password 字段**，密码被静默丢弃（管理员看到"已更新"但密码根本没变）。

**修复**：
1. 后端 `updateTeacher` 增加 `password` 字段处理（6-20位校验 + bcrypt 哈希存储）
2. Web端教师列表增加独立的「重置密码」按钮，调用 `reset-password` 端点（默认密码 1314521）
3. 后端 `resetPassword` 方法放宽密码长度限制：从 `< 8` 改为 `< 6 || > 20`，使 1314521（7位）、1314520（7位）、123456（6位）均可使用

### 问题2：Web端设置了班主任学科信息后页面不显示，仍提示"未设置"

**根因**：班级实体 `ClassItem.subjects` 后端支持存储学科数组，但 Web 端的班级列表 **从未展示 subjects 列**，编辑/新增表单 **从未提供学科输入框** → 前端从未发送 subjects 字段。

**修复**：
1. Web端班级列表新增「班主任学科」列，显示已设置的学科（逗号连接）或 "未设置" 标记
2. Web端班级编辑/新增表单增加「班主任任教学科」输入框（逗号分隔）
3. 小程序端班级列表增加学科显示行
4. 小程序端班级表单增加学科输入框

### 问题3：小程序端校管理员登录后直接弹出要求重新登录

**根因**：非单一原因，而是多个因素叠加：
- 校管理员密码可能被超管通过 Web 端编辑表单设置，但由于问题1类似的原因（Web端校管编辑密码字段同样未被后端处理），密码可能未实际写入
- 云托管链路 `wx.cloud.callContainer` 30 秒超时可能导致首次 API 调用失败
- `apiCall()` 中 401 处理直接 `uni.reLaunch` 到登录页，用户感知为"被踢出"

**修复**：
1. Web端校管编辑表单密码通过专用的 `PATCH /admin/school-admins/:id/password` 端点提交
2. Web端校管列表增加独立的「重置密码」按钮（默认密码 1314520）
3. 后端 `resetAdminPassword` 增加 6-20 位长度校验

### 问题4：小程序端教师用户无法登录进入

**根因**：与问题1同根——教师密码未实际写入。校管在 Web 端或小程序端创建/编辑教师时填写的密码被静默忽略，导致教师实际无密码或使用错误的密码。

**修复**：同问题1。

---

## 密码策略统一（需求第6条）

| 规则 | 实现 |
|------|------|
| 密码长度 ≥ 6 位 | `resetPassword` / `updateTeacher` / `resetAdminPassword` 统一校验 `>= 6` |
| 密码长度 ≤ 20 位 | 统一校验 `<= 20` |
| 超管重置校管默认密码 | 1314520（7位，符合 6-20 规则） |
| 校管重置教师默认密码 | 1314521（7位，符合 6-20 规则） |
| 班主任重置家长默认密码 | 123456（6位，符合 6-20 规则） |
