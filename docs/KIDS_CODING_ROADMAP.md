# 少儿编程功能扩展路线图（三阶段全量）

> 目标：把现有「老师开放给家长 → 学生练习」的少儿编程，从"玩具级拖拽"升级为"能教、能练、能评、能迭代"的学习系统。
> 现状基线：积木拖拽编辑器 + 小乌龟舞台 + 运行引擎（`repeat` 积木、`MAX_STEPS=5000` 步数保护、`execBlock` 步进计数）、教师作品画廊 + 学生练习 CRUD（`studentId` 隔离）、启动迁移器（`main.ts` 扫描 `migrations/*.sql`）。
> 阅读约定：每项给出「学习价值 / 系统改动 / 验收点」；⚙️ 表示依赖前置引擎能力。

## 0. 总览

| 阶段 | 主题 | 功能 | 优先级 | 主要依赖 |
|------|------|------|--------|----------|
| 一 | 学习闭环 + 核心概念（地基） | 任务卡、作业提交、教师点评、变量、条件、运算、单步调试 | P0 | 运行引擎增强 |
| 二 | 表达 + 同伴 | 自定义函数、列表、多角色、文字输出、班级作品墙、家长周报 | P1 | 阶段一引擎 |
| 三 | 打磨 + 前瞻 | 音效、画笔美化、引导教程、成就徽章、AI 启蒙积木 | P2 | 阶段一二 |

**关键路径**：先打牢运行引擎（变量作用域 + 表达式求值 + 条件/分支 + 调用栈），阶段一 4/5/6 与阶段二 8/9 全部建立其上；数据层（挑战/作业/点评/徽章）各自独立成实体+迁移+控制器，互不阻塞。

## 阶段一：学习闭环 + 核心概念（P0，先做）

### 1.1 任务卡 / 课堂挑战 ⚙️
- **学习价值**：目标驱动学习，把"画正方形/五角星"变成可验收任务，培养分解与算法思维。
- **系统改动**
  - 新增实体 `CodingChallenge`（`kids_coding_challenges`）：`teacherId`、`classId`、`title`、`description`、`prompt`（题干）、`expected`（判题目标：如目标坐标/轨迹/步数/图形特征）、`difficulty`、`createdAt`。
  - 新增迁移 `AddKidsCodingChallenges.sql`（沿用 `information_schema` 幂等模式）。
  - 新增 `ChallengeController`（`@Roles('teacher')`）：`POST /kids-coding/challenges`、`GET /mine`、`GET /:id`、`PATCH /:id`、`DELETE /:id`，按 `teacherId` 隔离。
  - 家长端 `GET /parent/kids-coding/challenges`：列出本班已开放挑战（复用 `classId + publishedToParent` 思路，或新增 `assignedClassIds`）。
- **验收点**：教师建题并发布到某班 → 该班家长端「挑战」页可见 → 学生可基于挑战新建练习。

### 1.2 作业提交 vs 草稿
- **学习价值**：区分"随便练"与"交作业"的权责感，承接任务卡形成作业流。
- **系统改动**
  - `CodingProject` 实体加 `challengeId VARCHAR(64) NULL`、`submitted TINYINT(1) DEFAULT 0`、`submittedAt DATETIME NULL`（迁移 `AddKidsCodingProjectSubmission.sql`）。
  - 家长端 `createPracticeProject`/`updatePracticeProject` 支持传 `challengeId`；新增 `POST /parent/kids-coding/:id/submit` 提交（置 `submitted=1`）。
  - 教师端新增「作业批改」视图：按 `challengeId` 聚合本班提交。
- **验收点**：学生从挑战进入练习 → 保存为草稿 → 点"提交作业" → 教师端对应挑战下出现该生提交。

### 1.3 教师点评 / 评语
- **学习价值**：接收反馈、迭代改进——学习闭环最关键的一环。
- **系统改动**
  - 新增实体 `CodingReview`（`kids_coding_reviews`）：`projectId`、`challengeId`、`teacherId`、`studentId`、`rating TINYINT`、`comment TEXT`、`createdAt`。
  - 迁移 `AddKidsCodingReviews.sql`。
  - 教师端 `POST /kids-coding/reviews`（对某提交写评语+星级）；家长端 `GET /parent/kids-coding/:id/review` 读取本人作品的教师反馈。
- **验收点**：教师对某提交写评语 → 学生端该作品显示评语与星级 → 可据此修改重交。

### 1.4 变量积木 ⚙️
- **学习价值**："状态"概念，从死步骤升级到动态数据驱动。
- **系统改动**
  - 运行引擎新增**变量作用域**（执行上下文 `scope: Map<string, any>`）：积木 `设变量 x = 0`、`x 增加 1`、`使用 x`。
  - 积木面板"数据"分组新增上述三类；`execBlock` 在执行时对变量节点做读写。
  - 序列化/反序列化兼容（现有 `blocks: any` JSON 已可承载）。
- **验收点**：学生用变量画"边长递增的螺旋"并运行成功；作用域在多次运行间隔离。

### 1.5 条件判断 if / else ⚙️
- **学习价值**：逻辑决策与分支思维，计算思维核心。
- **系统改动**
  - 引擎加**条件求值**：`如果 <条件> 则 ... 否则 ...` 积木，条件由表达式求值器（`1.6`）产出布尔。
  - `execBlock` 支持带子块的控制结构（children 递归执行）。
- **验收点**：用 `如果 x > 5 则 转向 否则 前进` 写出分支程序并正确运行。

### 1.6 运算积木（表达式求值器）⚙️
- **学习价值**：数学与编程的连接（角度、对称、概率、比较）。
- **系统改动**
  - 引擎新增**表达式求值器**：支持 `+ - × ÷`、`随机(1,10)`、`> < =`、`与/或`、`取余`；变量可参与。
  - 积木面板"运算"分组；数值类积木参数支持"常量 | 变量 | 表达式"三态。
- **验收点**：`前进 随机(20,50)`、`如果 x > 3 与 y < 8` 等组合可运行并符合数学预期。

### 1.7 单步调试 / 高亮执行
- **学习价值**：看清单步发生了什么，培养调试与迭代思维。
- **系统改动**
  - 复用现有 `stepCount` 计数，新增"单步模式"：`run(mode: 'auto'|'step')`；`step` 模式下每执行一块 `await` 一个可暂停的 tick，并把"当前块 id"暴露给前端高亮。
  - 前端编辑器加「▶ 运行 / ⏸ 暂停 / ⏭ 单步 / 🐢 慢速」控件，画布上高亮当前执行积木。
- **验收点**：开启单步后，积木逐块高亮、小乌龟逐动作移动；可暂停/继续；不突破 `MAX_STEPS`。

> 阶段一依赖关系：`1.4→1.5→1.6` 共享同一引擎增强；`1.1/1.2/1.3` 为数据层，可并行；`1.7` 独立于引擎概念，仅复用步进计数。

## 阶段二：表达 + 同伴（P1）

### 2.1 自定义函数 / 积木 ⚙️
- **学习价值**：抽象与复用，写出"干净"的程序。
- **系统改动**
  - 引擎加**函数定义与调用栈**：积木 `定义 我的积木(参数) { ... }`、调用节点；支持参数传递与返回。
  - 编辑器支持"我的积木"面板与拖入调用。
- **验收点**：定义 `画正多边形(边数,边长)` 后多次调用画出不同图形。

### 2.2 列表 Lists ⚙️
- **学习价值**：数据结构雏形，批量处理与模式。
- **系统改动**
  - 引擎变量扩展支持**列表类型**；新增 `加入列表`、`列表第 i 项`、`遍历列表` 积木（遍历复用 `repeat` 的循环框架）。
- **验收点**：用列表存一组角度，遍历画出复杂对称图案。

### 2.3 多角色 / 多小乌龟 ⚙️
- **学习价值**：并发与协作的直觉。
- **系统改动**
  - 引擎支持**多执行体**：每个角色独立坐标/朝向/画笔；新增 `当接收到 消息`/`广播 消息` 积木做角色协同。
  - 编辑器支持"添加角色"，舞台渲染多 turtle。
- **验收点**：两个角色收到同一消息后各自画出对称的一半。

### 2.4 文字输出 / 对话窗
- **学习价值**：用程序讲故事、做表达，连接语文与编程。
- **系统改动**
  - 新增"输出"面板；引擎 `说 "..."`/`打印` 积木把文本推到输出区（与现有舞台并列）。
- **验收点**：程序运行后在输出框显示对话/计算结果。

### 2.5 班级作品墙（教师审核后互看）
- **学习价值**：同伴学习、成就感、正向激励。
- **系统改动**
  - `CodingProject` 加 `showInGallery TINYINT DEFAULT 0`；教师端"设为作品墙展示"开关；家长端 `GET /parent/kids-coding/gallery` 列出本班被教师精选的作品（只读）。
  - 注意：仅展示教师精选 + 同班，避免隐私与未审核内容外泄。
- **验收点**：教师精选某生作品 → 本班其他家长/学生在作品墙可见且不可改。

### 2.6 家长学习周报
- **学习价值**：让家长看见"孩子学到了什么"，形成家校闭环。
- **系统改动**
  - 聚合统计：本周练习数、提交作业数、获评星级数、掌握概念（变量/条件/函数使用痕迹）。
  - 周报聚合接口 `GET /parent/kids-coding/weekly-report`；新增推送能力：家长端 `POST /parent/kids-coding/weekly-report/push`（手动推送到消息中心）+ 超管端 `POST /admin/kids-coding/weekly-report/push-all`（批量推送，遍历近 7 天有活动的学生），均经 `MessageService` 写入站内信（type=`coding_weekly`）。
  - 自动推送：已内置 `@nestjs/schedule` 定时任务（`KidsCodingBatchService` 的 `@Cron('0 8 * * 1')`，每周一 08:00 自动扫描并推送全校周报），`ScheduleModule.forRoot()` 在 `app.module` 注册；同时保留超管端 `POST /admin/kids-coding/weekly-report/push-all` 供手动触发，二者复用同一 `pushAllWeeklyReports()` 逻辑，避免重复。
- **验收点**：家长在周报页点「推送周报到消息中心」即收到站内信周报；超管批量推送覆盖全部活跃学生家长。

## 阶段三：打磨 + 前瞻（P2）

### 3.1 音效 / 音乐
- **学习价值**：跨学科（节奏=循环），提升投入度。
- **系统改动**：轻量 `播放音效`/`演奏音符` 积木（Web Audio API），不阻塞主引擎。

### 3.2 画笔颜色 / 粗细美化
- **学习价值**：几何 + 色彩审美，作品更富表现力。
- **系统改动**：扩展现有 pen 积木为 `落笔(颜色, 粗细)`、`设颜色`、`设粗细`，画布支持彩色描边。

### 3.3 引导式教程 / 示例模板
- **学习价值**：零基础可上手，降低弃课率。
- **系统改动**：模板库（预置"画正方形/星星/房子"等）+ 编辑器内分步引导浮层；模板即只读 `CodingProject` 示例。

### 3.4 成就徽章 / 进度
- **学习价值**：游戏化持续动力。
- **系统改动**：新增 `CodingBadge` 实体（如"首次提交""画出对称图""用上变量"），规则引擎在提交/运行时判定授予，家长端展示。

### 3.5 AI 启蒙积木（前瞻）
- **学习价值**：AI 素养启蒙，把"识别/生成"拆成儿童可操作小块。
- **系统改动**：预留 `AI` 分组（如 `识别我画的图形`、`和 AI 说 ___`），后端接轻量模型/规则，前端做安全护栏（仅限教育场景、内容过滤）。

## 落地顺序建议（里程碑）

1. **M1 引擎地基**：实现 1.4/1.5/1.6 的共享引擎（变量作用域 + 表达式求值 + 条件分支 + 控制结构 children 递归），配套单步调试 1.7。
2. **M2 学习闭环**：1.1 任务卡 + 1.2 作业提交 + 1.3 教师点评（数据层三件套）。
3. **M3 表达扩展**：2.1 函数 + 2.2 列表 + 2.3 多角色 + 2.4 文字输出。
4. **M4 同伴与家校**：2.5 作品墙 + 2.6 家长周报。
5. **M5 打磨前瞻**：3.1~3.5 按需排期。

> 每完成一项：新增对应迁移脚本（纳入启动迁移器）、更新 `KIDS_CODING_BUILD_VERIFICATION.md` 验证状态、跑 `vue-tsc -b` + `vite build` + `nest build` 验证。
