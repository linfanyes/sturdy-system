## 四、失败根因分析

### 4.1 数据规模相关（约 40% 失败）

测试用例中硬编码了基于 20 校 × 48 班 × 60 生数据集的期望值（如 ≥200 教师、≥50 学生），但在快速测试模式下使用的是小规模数据集。

**建议**：修改为基于比例的断言（如 `>= STUDENTS_PER_CLASS`），或增加环境判断。

### 4.2 家长登录失败（约 30% 失败）

多个家长测试用例因学号登录 401 失败。种子数据中家长账号的密码可能未正确设置，或登录端点行为变更。

**建议**：检查种子数据中 `student.parentPassword` 字段设置，确认家长账号创建逻辑。

### 4.3 API 返回结构变更（约 20% 失败）

部分用例期望的返回字段（如 `id`、`schoolName`）在最新版本中缺失或重命名。

**建议**：更新测试用例中的断言以匹配当前 API 契约。

### 4.4 服务异常（约 10% 失败）

课表服务、成绩分析服务返回 500 错误，需排查具体原因。

**建议**：针对 500 错误进行专项调试。

## 五、优化建议

### 5.1 代码优化

1. **【Critical】修复暗色模式背景**：Login.vue 的背景渐变和装饰元素需要添加 `.dark` 覆盖
2. **【Critical】修复重复 CSS 规则**：style.css 中删除重复的 `.dark .btn-primary`
3. **【Warning】修复无障碍访问**：密码可见性按钮移除 `tabindex="-1"`
4. **【Warning】修复小程序兼容性**：将 HTML `div` 改为 `<view>`
5. **【Warning】修复 CSS 选择器**：super/Dashboard.vue 死代码清理

### 5.2 测试用例优化

1. **数据规模自适应**：将硬编码期望值改为基于种子数据常量的相对断言
2. **家长登录修复**：排查并修复种子数据中家长账号密码设置逻辑
3. **API 契约同步**：更新断言以匹配当前 API 返回结构
4. **课表服务排查**：针对 500 错误进行专项调试

### 5.3 流程优化

1. **快速测试模式**：保留 `quick-run.ts` 小规模数据集快速验证
2. **CI 集成**：将 QA 测试集成到 CI 流水线，提交前自动验证
3. **定期全量测试**：每周执行一次完整数据集（20 校）的回归测试
