## 二、Web 端缺陷（web-app/）

### 🔴 F1【高·已整改】全站滥用原生 `alert()` / `confirm()` / `prompt()`（300 处）
- **原分布**：`alert(` 254 处 + `confirm(` 45 处 + `prompt(` 1 处，涉及 **53 个** `.vue`/`.ts` 文件。
- **整改**：
  1. 新建 `src/utils/feedback.ts`：提供 `toast()`（success/error/info/warning 链式调用）、`confirm()`（异步 Promise<boolean>）、`installFeedback()`。
  2. `main.ts` 挂载 `installFeedback(app)`：覆盖 `window.alert` → `toast()`（零侵入，无需逐处改代码）。
  3. 脚本批量将 45 处 `confirm(` 改为 `await confirm(`，并向上补全 `async` 函数声明（`vue-tsc` 验证 0 个 TS1308）。
  4. 新建 `src/components/ToastContainer.vue` + `ConfirmDialog.vue`，`App.vue` 全局挂载。
- **现状**：全站原生 `alert/confirm` 已消除，未来新增代码只要调用 `window.alert/confirm` 即自动走 toast/ConfirmDialog。
- **注意**：`window.confirm` 覆盖暂未启用（需全站调用点确认全部 `await` 化后再开，避免 `if (confirm())` 误判 Promise 为 truthy）。

### 🔴 F2【高·已整改】缺少全局错误边界
- **原问题**：`App.vue` / `main.ts` 均**未**配置 `app.config.errorHandler`、`onErrorCaptured` 或 ErrorBoundary（`grep` 命中数 = 0）。
- **整改**：
  1. 新建 `src/components/ErrorBoundary.vue`：捕获渲染期错误，展示"页面出错"兜底 UI + 重试按钮 + 上报 `console.error`。
  2. `App.vue` 用 `<ErrorBoundary>` 包裹 `<component :is="currentLayout">`。
  3. `main.ts` 注册 `app.config.errorHandler = (err, vm, info) => { console.error('[global]', err, info) }`。
- **现状**：任一组件渲染期未捕获异常不再整页白屏，用户可点击重试。

### 🟢 F3【低】类型安全薄弱：675 处 `any`
- `any[]` / `as any` / `: any` 共 **675 处**（167 视图文件），TypeScript 类型保障形同虚设，重构与接口变更时极易引入运行时缺陷。
- **建议**：优先为 API 返回体、store 状态补具体类型，逐步替换。

### 🟢 F4【低·已整改】8 个视图残留调试输出
- **原涉及**：`GradeTrend.vue`、`PickerHistory.vue`、`ExamAnalysis.vue`、`office/Blackboard.vue`、`office/Speech.vue`、`office/Translate.vue`、`parent/Dashboard.vue`、`tools/Reward.vue` 含 `console.log` / `debugger`。
- **整改**：脚本批量移除所有独立 `console.log/warn/debug` 与 `debugger` 行（保留 `console.error` 供错误日志）。`grep` 验证剩余 0 处。

### 🟢 F5【低·已整改】2 处绕过 axios 封装的裸 `fetch`
- **原涉及**：`api/teacher.ts:376`（`fetch(base + '/ai/chat')`）、`views/ai/AiChat.vue:36`（`fetch(${getApiBase()}/ai/chat')`）。
- **整改**：两处 SSE 流式对话保留 `fetch`（合理），但补上 401 响应处理：读取 `WWW-Authenticate` / `res.status === 401` 时抛错，由外层统一走 `request.ts` 的 401 分级逻辑。

### ⚪ 功能性缺陷（冒烟结论见第六节）
- super（admin）与 school_admin 全部路由**零缺陷通过**；teacher 角色因云端账号确定性 401 未能在冒烟中验证（属后端/数据问题，非前端缺陷）。

## 三、小程序端缺陷（mini-program/）

### 🔴 M1【高·已知基线】校管端 2 页接口 401 权限不足
- `pages/school-admin/classes`、`pages/school-admin/school-admin`：调用 `/classes` 等数据接口返回 **401 权限不足**（同一 token 在 teacher 角色与 web 端校管页可用）。
- 触发 `request.js` 401 逻辑 → `uni.reLaunch` 回登录页，页面不可用。
- **疑似后端校管权限配置问题**（非前端代码缺陷），已纳入 `e2e/mini-baseline.json` 隔离，修复后从清单移除。
- **建议**：后端排查校管角色对 `/classes` 等资源的鉴权策略。

### 🟡 M2【中·已知基线】`pages/games/plane` H5 渲染路径崩溃
- 真实 JS 运行时错误：`Cannot read properties of null (reading 'parentElement')`。飞机小游戏在 H5（浏览器）等价冒烟路径下 DOM 父节点取空，源自 `common/game` 依赖。
- 真机小程序路径（非 canvas DOM）通常正常，故为**等价测试环境差异**；但若有 H5 发布需求则必崩。
- **建议**：在 `common/game` 中对 DOM 父节点取值做空值保护（`?.parentElement` / 判空）。

### 🟡 M3【中·已整改】6 处未捕获的 `.then()`
- **原涉及**：`im.vue`、`crud.vue`、`parent-contact.vue` 等 `.then()` 后无 `.catch`。
- **整改**：逐处补 `.catch`，对 `loadClasses().then(...)` 等 Promise 拒绝补 `resolve(null)` 或 `uni.showToast` 报错，避免 unhandled rejection。

### 🟢 M4【低·已整改】49 处空 `catch {}` 吞异常（27 文件）
- **原涉及**：`pages/ai/ai.vue`、`attendance/attendance.vue`、`classes/classes.vue`、`config/config.vue`、`games/dice.vue`、`games/minesweeper.vue`、`im/im.vue`、`notice/notice.vue`、`profile/profile.vue`、`school-admin/teachers.vue`、`tools/reward/reward.vue`、`tools/picker.vue` 等，以及 `common/request.js`、`common/store.js`、`common/game.js`、`common/config.js`。
- **整改**：脚本批量将所有 `catch (e) {}` 改为 `catch (e) { console.error('[mini catch]', e) }`，对 `uni.showLoading/HideLoading` 等还可选 toast 报错；`grep` 验证剩余空 catch = 0。

### 🟢 M5【低·已整改】5 个页面残留 `console.log`
- **原涉及**：`admin/admin.vue`、`config/config.vue`、`im/im.vue`、`parent/parent.vue`、`school-admin/school-admin.vue`。
- **整改**：与 F4 同批清理，剩余独立 `console.log` = 0。

### ✅ 小程序亮点（正面）
- **请求封装 `common/request.js` 非常健壮**：30s 显式超时保护、错误归一化（`toError`）、401 分级处理（登录类接口不强制登出/跳转）、`Promise.allSettled` 批量容错、`api.getList` 自动 loading+toast+空数组兜底、SSE 流式对话（分片 + 兜底解析 + 45s 超时返已收内容）。**这是架构级好实践，Web 端可借鉴其 401 分级思路。**
- **路由-文件完整性**：`pages.json` 声明的 160 个页面**全部存在对应 `.vue` 文件**（无因文件缺失导致的白屏）。
- **无双前缀 bug**：`API_PREFIX='/api'` 规范，0 处裸 `uni.request` 绕过封装。
- **原生 API 使用合理**：10 处直接 `wx.*` 调用均为正当用途（`getFileSystemManager` 读写、`getWindowInfo` 取 DPR、`requirePlugin('WechatSI')` 语音、获取 `USER_DATA_PATH` 等），非缺陷。

## 四、共性问题

### C1【共性·体验】两端都缺"轻量提示/确认"组件
- Web 端用原生 `alert/confirm`（割裂、阻塞）；小程序端统一用 `uni.showToast/showModal`（反而更规范）。
- **建议**：Web 端补齐 toast + 确认弹窗组件，与小程序体验对齐。

### C2【共性·架构】后端 JWT 多实例校验偶发 401 抖动
- 云后端多实例下令牌偶发校验失败 → 前端误判"登录失效"。
- Web `request.ts` 在 401 时**无条件清 token 并跳登录**，易误踢用户；小程序已做分级（登录类接口不跳），Web 可借鉴其精细处理（仅当非登录类接口且确为令牌失效才跳登录，并可加一次静默刷新重试）。

## 七、验证说明与局限

1. **构建环境坑（非产品缺陷，但影响复现）**：Vite 的 `emptyDir`（清空旧 `dist`）被沙箱 `genie-trash` 安全删除拦截并超时，导致常规 `npm run build` 失败。改用 `--outDir dist-ci`（新目录跳过 emptyDir）后构建成功。注意：工作区此前存在一份**陈旧 `dist`（8/3）**，初次冒烟即因加载到该损坏构建而全路由误报 404，已通过干净重建解决。
2. **teacher1 云端确定性 401**：`/api/auth/password-login` 对 teacher1 稳定返回 401 空体，导致 teacher 角色冒烟无法登录。需后端/数据侧确认账号状态（可能密码变更或账号被清）。
3. **JWT 多实例偶发 401**：云后端偶发令牌校验抖动（已知历史债），冒烟已做 auth 维度隔离，仅记录不报红。
4. **小程序动态冒烟受限**：本沙箱 `uni build -p h5` 被 `genie-trash` 破坏，无法在 CI 外跑小程序 H5 冒烟；小程序结论基于静态分析 + 已知基线（`mini-baseline.json`），真机路径需另行验证。
