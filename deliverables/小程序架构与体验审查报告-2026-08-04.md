## 二、🔴 严重缺陷

### A1【严重·架构】路由角色守卫 `PAGE_ROLES` 严重不全，导致校管/家长几乎无法访问任何页面

**位置**：`common/route-guard.js:31-40`

**现象**：`canAccess()` 对未在 `PAGE_ROLES` 中声明的页面执行默认策略：
```js
if (!allowedRoles) {
  if (role !== ROLE.TEACHER) return false  // 非教师一律拦截
}
```

当前 `PAGE_ROLES` 仅声明了 6 个页面：
- `pages/login/login`（全员公开）
- `pages/parent-login/parent-login`（全员公开）
- `pages/admin/admin`（超管）
- `pages/school-admin/school-admin`（校管）
- `pages/parent/parent`（家长）
- `pages/parent/compare`（家长）

**影响面（自动化验证）**：

| 角色 | 可访问页面 | 被拦截页面 | 拦截率 |
|------|-----------|-----------|--------|
| super（超管） | 3（login + parent-login + admin） | 157 | 98% |
| school_admin（校管） | 2（login + parent-login + school-admin） | 157 | 98% |
| parent（家长） | 3（login + parent-login + parent + compare） | 156 | 97% |
| teacher（教师） | 156（被拦截 admin/school-admin/parent/compare） | 4 | 2.5% |

**具体不可用页面举例**：
- 校管：`school-features`、`teachers`、`classes`、`students`、`notices` 全部被拦截
- 家长：`parent-resource-library` 被拦截
- 超管：除 `admin` 外几乎所有页面被拦截（包括本应能访问的 school-admin 管理页）

**根因**：`PAGE_ROLES` 在开发初期仅覆盖了各角色"首页"，后续新增的大量角色专属页（teachers/classes/students/notices/features/resource-library 等）未同步补入声明。

**建议**（P0 修复）：
1. **短期止血**：对 `school-admin/`、`parent/`、`admin/` 等前缀做批量白名单（前缀匹配），避免逐页声明。
   ```js
   if (path.startsWith('pages/school-admin/') && role === ROLE.SCHOOL_ADMIN) return true
   if (path.startsWith('pages/parent/') && role === ROLE.PARENT) return true
   if (path.startsWith('pages/admin/') && role === ROLE.SUPER) return true
   ```
2. **长期重构**：在 `pages.json` 每个页面对象中增加 `roles` 字段，启动时解析生成 `PAGE_ROLES`，避免代码与配置双维护。
3. 超管（super）建议默认放行所有页面（后端再控制数据权限），避免前端误拦。

## 三、🟡 中等缺陷

### B1【中】grades.vue 全部科目矩阵输入框宽度仅 150rpx，手机输入困难

**位置**：`pages/grades/grades.vue` 模板中 `.m-score`

**问题**：`150rpx ≈ 75px`，在主流手机（375px 宽）上可点击区域过小，且 `type="digit"` 输入法键盘容易遮挡内容。

**建议**：将输入框最小宽度提升至 `180rpx`，或改用弹出式数字键盘 / 底部滑动录入。

### B2【中】grades.vue 雷达图 canvas 宽度 600rpx 溢出 modal

**位置**：`pages/grades/grades.vue` `.radar-cv` 样式

**问题**：modal 可用宽度约 `576rpx`（640rpx - 32rpx×2 padding），canvas 固定 `600rpx` 会被裁剪。

**建议**：改为 `width: 100%` 或 `max-width: 520rpx`。

### B3【中】grades.vue 全部科目矩阵一次渲染 400+ input，滚动卡顿风险

**问题**：50 学生 × 8 科目 = 400 个 `<input>`，uni-app 对大量表单控件的渲染和焦点管理优化有限，滚动时可能出现掉帧。

**建议**：分页/分屏录入（每次只渲染 20 行）、或使用 `recycle-view` 虚拟列表、或改为"点击学生弹出编辑面板"的单条录入模式。

### B4【中】students.vue "加载更多"按钮无防抖，快速点击累积 page

**位置**：`pages/students/students.vue:48` `@click="page++"`

**问题**：无 `loadingMore` 状态保护，1 秒内点击 5 次会累积 `page+=5`，一次性请求 5 倍数据。

**建议**：加 `loadingMore` ref，请求期间禁用按钮。

### B5【中】im.vue 底部输入栏未避让安全区

**位置**：`pages/im/im.vue:53-57` `.inputbar`

**问题**：`.inputbar` 未使用 `safe-bottom` 工具类，在 iPhone X/14 Pro 等设备上可能被 Home Indicator 遮挡，输入框底部无法点击。

**建议**：给 `.inputbar` 增加 `padding-bottom: env(safe-area-inset-bottom)`。

### B6【中】dashboard.vue 快捷操作区 5 列在窄屏（< 375px）下拥挤

**位置**：`pages/dashboard/dashboard.vue:64-85` `.quick-actions`

**问题**：5 列等宽网格在 375px 屏幕上每列仅约 75rpx 宽，图标+文字密集，老年教师可能误触。

**建议**：改为 4 列 + 换行，或使用 `grid-template-columns: repeat(auto-fit, minmax(120rpx, 1fr))` 自适应。

## 四、🟢 轻微缺陷

### C1【低】login.vue 存在大量未使用样式

**位置**：`pages/login/login.vue` `<style>` 块

**问题**：`.mask`、`.sheet`、`.sh-*`、`.roles2`、`.r2`、`.inp`、`.ok` 等 class 在 template 中无引用，增加包体积且维护时易混淆。

**建议**：清理未使用样式，或提取为公共组件后复用。

### C2【低·误判】pages.json 命名相似但功能不同，非重复页面

**原判断**：`pages/class-activity/class-activity` 与 `pages/class-activities/class-activities`、`pages/papers/papers` 与 `pages/paper-queries/paper-queries` 被怀疑为重复。

**复核结论**：四者均为**小程序独有**（Web 端无对应页面），且调不同 API、功能不同：
- `class-activity`：按班级过滤活动快速查看（`/class-activities?classId=`，简单展示+删除）
- `class-activities`：全部活动完整管理（`/class-activities`，带 skeleton/empty/编辑）
- `papers`：AI 生成试卷列表（`/generated/papers`）
- `paper-queries`：AI 查询历史管理（`/generated/queries`，支持编辑/删除）

**结论**：命名相似但功能独立，**无需合并**。

### C3【低】70+ 页面开启 `enablePullDownRefresh`，维护成本高且体验不一致

**现象**：pages.json 中约 70 个页面声明了 `enablePullDownRefresh: true`。

**问题**：
1. 每个页面需单独实现 `onPullDownRefresh`，容易遗漏或逻辑不一致；
2. 用户难以记忆哪些页面可下拉，造成"下拉无效"挫败感；
3. 与页面内 `scroll-view` 嵌套时易触发滚动冲突（scroll-view 内部滚动 vs 页面级下拉）。

**建议**：仅对列表页（students / classes / grades / notices 等）保留下拉刷新，详情页/工具页关闭；对列表页统一封装 `useListRefresh()` composable。

## 五、✅ 架构与体验亮点

### D1 请求层 `request.js` 架构级健壮性
- 30s 显式超时 + 45s SSE 流式超时，避免微信框架无限挂起
- 401 分级：登录类接口不强制跳转，由调用方 toast 展示具体错误
- `getList` 自动 loading + toast + 空数组兜底，减少样板代码
- `streamChat` 分片解析 + 中断 + 兜底解析，AI 对话体验有保障
- 演示模式（Mock）与生产构建自动隔离

### D2 App.vue 主题与安全区体系完善
- CSS 变量实现亮/暗色主题，`--fz-scale` 控制字体缩放
- `env(safe-area-inset-*)` 全局工具类 + 底部组件统一避让
- 全局盒模型防横向溢出、`-webkit-text-size-adjust` 防 iOS 放大
- 多角色会话恢复逻辑清晰

### D3 tabBar 与子包拆分合理
- tabBar 严格 5 项（微信上限），无违规
- 3 个子包（games/tools/ai）将非核心功能隔离，主包体积可控
- `preloadRule` 预加载 tools 子包，进入工具箱时更快

### D4 parent.vue 错误态与加载态对齐 Web 端
- `load-err` + `loading-mask` 与 Web 端 spinner 视觉统一
- 多娃切换、订阅消息引导、Tab 内容隔离等家长场景考虑周全

## 七、布局/排版/UX 总结

### 优点
- 卡片式布局统一（`.card` / `.ov` / `.stat-card`），信息层级清晰
- 空态（`EmptyState`）与错误重试态（`load-err`）已形成规范
- emoji 图标使用一致（🏫👀📊📝🔔 等），降低 icon font 依赖
- `word-break: break-word` 全局应用，长文本不截断

### 待改进
-  grades 矩阵输入体验（B1/B2/B3）
-  im 底部栏安全区（B5）
-  dashboard 快捷区响应式（B6）
