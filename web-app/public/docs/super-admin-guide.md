## 1. 概述

超级管理员（以下简称"超管"）是园丁工作台平台级别的最高权限角色，拥有跨学校、跨角色的全局管理能力。超管可管理所有学校、学校管理员、教师、学生，查看全平台审计日志，配置平台级参数（AI、微信、IM 等），维护 AI 服务商清单，按学校控制功能包开关，以及跨校审计考试与成绩数据。

**超管工作台路径**：登录后自动跳转至 `/super`。超管只能访问 `/super/*` 路由，无法访问学校管理员、教师或家长的功能页面。

## 2. 登录方式

### 2.1 登录入口

打开园丁工作台 Web 端，进入登录页。系统会自动识别用户角色：输入超管账号与密码后，将直接进入超管工作台（`/super`）。

### 2.2 登录流程

1. 在登录页输入**用户名**和**密码**。
2. 点击「开始工作 →」按钮。
3. 系统验证凭据后，自动识别角色并跳转至对应工作台。超管账号将跳转至超管工作台。

### 2.3 便捷功能

- **最近登录**：登录页会记录最近 3 条登录账号，点击即可快速填充用户名。
- **密码可见切换**：点击密码框右侧眼睛图标，可切换密码可见/隐藏状态。
- **大写锁定提示**：如键盘开启大写锁定，输入密码时会出现提示。
- **忘记密码**：超管密码由系统初始化设定，如需重置请联系系统运维人员。

### 2.4 角色自动识别

系统根据登录账号自动识别角色，并跳转至对应工作台：

| 角色 | 路由前缀 | 说明 |
|------|----------|------|
| 超级管理员 | `/super` | 平台全局管理 |
| 学校管理员 | `/school-admin` | 本校管理 |
| 教师 | `/teacher` | 教学管理 |
| 家长 | `/parent` | 家长中心 |

### 2.5 安全说明

- 所有登录凭据由后端安全校验，通过 JWT 令牌进行后续请求认证。
- JWT 过期后需重新登录（过期时间可在平台配置中设置）。
- 本地存储仅用于 UI 层面的角色识别与菜单显隐，真正的数据权限由后端 `@Roles` + JWT（`t.sub`）强制校验。本地篡改无法越权读取数据。
- API 请求层在收到 401 响应时会清除本地登录态并跳转登录页，形成闭环防御。

## 3. 工作台概览（Dashboard）

路径：`/super`（默认首页）

超管登录后首先进入工作台概览页，该页面集中展示全平台的运行状态与关键指标。页面顶部显示欢迎横幅（含超管头像与姓名），下方依次排列各统计区域。

### 3.1 关键指标卡片（4 个）

4 张卡片水平排列，显示核心统计数据，点击可跳转至对应管理页：

| 卡片 | 图标 | 说明 | 点击跳转 |
|------|------|------|----------|
| **学校** | 学校图标 | 全平台学校总数 | `/super/schools` |
| **管理员** | 用户图标 | 全平台学校管理员总数 | `/super/admins` |
| **今日日志** | 时钟图标 | 当日产生的审计日志条数 | `/super/audit-logs` |
| **本周活跃** | 活动图标 | 近 7 天操作总数 | `/super/audit-logs` |

### 3.2 操作类型分布（环形图）

展示审计日志中各操作类型的占比统计。Top 5 操作类型以不同颜色区分（橙、蓝、绿、粉、棕），其余操作类型归入"其他"。支持的操作类型包括：创建教师、删除教师、重置密码、创建班级、删除班级、新增校管、删除校管等。

### 3.3 7 天操作活跃趋势（折线图）

展示最近 7 天每天的操作量变化趋势。横轴为日期（格式 `M/D`），纵轴为操作数量。折线颜色为蓝色（`#1C6FB3`），帮助超管快速判断平台的日常运营活跃度变化。

### 3.4 Top5 学校规模（横向条形图）

按教师数量聚合排名前 5 的学校，以黄油色渐变水平进度条直观展示各校规模对比。每行显示学校名称（截断省略）、进度条和教师数量。

### 3.5 各校操作热度（横向条形图）

基于最近 500 条审计日志聚合各校的操作数量，排名前 5 的学校以天蓝色渐变进度条展示。全局操作（无学校归属）标记为"全局操作"。

### 3.6 学校状态分布（环形图）

以环形图展示全平台学校的启用/停用状态比例。活跃学校以绿色（`#4AAE7A`）显示，停用学校以红色（`#e06c75`）显示。

### 3.7 平台核心指标（进度条组）

4 个进度条指标从不同维度衡量平台健康度：

| 指标 | 计算方式 |
|------|----------|
| 已启用学校 | 活跃学校数 / 学校总数 |
| 学校管理员 | 管理员总数 / (学校总数 x 2) |
| 审计活跃度 | 本周审计日志条数 / 50（上限目标） |
| 今日活跃度 | 今日审计日志条数 / 10（上限目标） |

### 3.8 最近操作记录（表格）

展示最新 10 条审计日志，包含以下列：

| 列名 | 说明 |
|------|------|
| 时间 | 当日显示时:分，非当日显示月/日 时:分 |
| 操作人 | 执行操作的用户名 |
| 动作 | 操作类型的中文标签 |
| 对象 | 操作目标名称或类型 |
| 学校 | 操作关联的学校名称 |

## 4. 学校管理

路径：`/super/schools`

管理全平台所有学校的基础信息，支持增删改查及启停控制。学校是数据隔离的基本单位，所有教师、学生、班级数据均归属于特定学校。

### 4.1 页面布局

- **顶部**：页面标题「学校管理」+「新增学校」按钮
- **统计卡片行**（3 张）：学校总数、启用数（绿色）、停用数（红色）
- **学校列表表格**：名称、编号、状态、地址、管理员数量、操作按钮
- **底部分页栏**：每页条数可选 5 / 10 / 20 / 50，支持上一页/下一页，显示当前页码与总条数

### 4.2 新增学校

**操作步骤**：

1. 点击右上角「新增学校」按钮，弹出新增弹窗。
2. 在弹窗中填写以下字段：
   - **名称**（必填）：学校名称，如"北京市第一小学"。
   - **编号前缀**（必填）：2 位大写字母或数字（如 `BJ`），输入时自动转换为大写并过滤非法字符。系统将自动生成 8 位完整编号，格式为：2 位前缀 + 5 位随机字符 + `H`。弹窗中会实时预览生成的编号格式（如 `BJ•••••H`）。
   - **地址**（可选）：学校地址。
   - **状态**：下拉选择「启用」或「停用」，新增默认启用。
3. 确认信息无误后，点击「保存」。
4. 保存成功后弹窗关闭，列表自动刷新，新学校出现在列表中。

### 4.3 编辑学校

**操作步骤**：

1. 在学校列表中找到目标学校，点击操作列的编辑按钮（铅笔图标）。
2. 弹出编辑弹窗，预填当前信息。可修改：
   - **名称**
   - **地址**
   - **状态**（启用/停用）
3. 编辑模式下**不可修改编号前缀**。
4. 修改完成后点击「保存」。

### 4.4 启用/停用学校

**操作步骤**：

1. 在学校列表中找到目标学校，点击电源图标按钮。
2. 系统即时切换学校状态，无需确认。按钮 title 提示当前可执行的操作（"停用"或"启用"）。
3. 状态变更即时生效：
   - **启用**：绿色标签 `bg-mint`，对应 `status: 'active'`
   - **停用**：红色标签 `bg-sakura`，对应 `status: 'inactive'`

> **注意**：停用的学校不会从系统中删除，其管理员、教师、学生数据仍然完整保留。

### 4.5 删除学校

**操作步骤**：

1. 在学校列表中找到目标学校，点击红色垃圾桶图标。
2. 系统弹出确认对话框："确定删除学校「XX」？此操作不可恢复。"
3. 点击确认后执行删除。
4. 删除后列表自动跳转到第一页并刷新。

> **警告**：删除学校操作不可恢复，请务必确认无误后再执行。

### 4.6 分页浏览

- 每页条数可选 5 / 10 / 20 / 50，默认 10 条。
- 切换每页条数时自动跳回第一页。
- 页面底部显示"第 X/Y 页"和"共 N 条"信息。

## 5. 校管理员管理

路径：`/super/admins`

管理所有学校的学校管理员账号。每个校管理员归属于一所学校，拥有该校的管理权限（教师管理、班级管理、学生管理、公告通知等）。

### 5.1 页面布局

- **顶部**：页面标题「学校管理员」+「新增管理员」按钮
- **统计卡片**（2 张）：管理员总数、启用数（绿色）
- **管理员列表表格**：姓名、用户名、所属学校、本校教师数、状态、创建时间、操作按钮
- **底部分页栏**：每页条数可选 5 / 10 / 20 / 50

### 5.2 新增校管理员

**操作步骤**：

1. 点击「新增管理员」按钮，弹出新增弹窗。
2. 填写以下字段：
   - **所属学校**（必填）：从下拉列表中选择目标学校。列表从 `/api/admin/schools` 接口加载。
   - **姓名**（必填）：管理员真实姓名。
   - **用户名**（必填）：用于登录的用户名。
   - **密码**（必填）：初始登录密码。
3. 点击「保存」完成创建。创建成功后弹窗关闭，列表跳转到第一页并刷新。

### 5.3 编辑校管理员

**操作步骤**：

1. 在管理员列表中找到目标管理员，点击编辑按钮（铅笔图标）。
2. 弹出编辑弹窗，可修改：
   - **所属学校**：从下拉列表重新选择。
   - **姓名**：修改姓名。
3. 编辑模式下**不显示用户名和密码字段**（用户名不可修改，密码需通过重置密码功能修改）。
4. 点击「保存」完成编辑。

### 5.4 重置密码

**操作步骤**：

1. 在管理员列表中找到目标管理员，点击钥匙图标（重置密码按钮）。
2. 弹出 `ResetPasswordModal` 重置密码弹窗，显示目标管理员姓名。
3. 系统默认新密码为 `1314520`，可在输入框中自定义新密码。
4. 点击确认执行重置。
5. 重置成功后，系统显示成功提示（含新密码信息）。

### 5.5 启用/停用校管理员

**操作步骤**：

1. 在管理员列表中找到目标管理员，点击电源按钮。
2. 系统即时切换管理员的 `enabled` 状态，无需确认弹窗。
3. 启用的管理员显示绿色标签"启用"，停用的显示红色标签"停用"。
4. 停用的管理员**无法登录系统**。

### 5.6 删除校管理员

**操作步骤**：

1. 在管理员列表中找到目标管理员，点击红色垃圾桶按钮。
2. 系统弹出确认对话框："确定删除？"
3. 点击确认后删除。操作不可恢复。

### 5.7 本校教师数

列表中的"本校教师"列显示每个管理员所属学校的教师数量，数据由 `/api/admin/teachers` 接口实时聚合。该列帮助超管快速了解各校的师资规模。

## 6. 教师管理

路径：`/super/teachers`

超管以只读视角查看全平台所有教师信息，支持按学校筛选、关键词搜索，以及导出 CSV 文件。

### 6.1 页面布局

- **顶部**：页面标题「教师管理（超管）」+「导出 CSV」按钮
- **筛选栏**：学校下拉筛选（含学校编号）、关键词搜索框（姓名/用户名/学科）、教师总数统计
- **教师列表表格**：学校（含编号）、姓名、用户名、学科、手机号、状态
- **底部分页栏**：每页 50 条，支持上一页/下一页

### 6.2 筛选教师

**操作步骤**：

1. 通过**学校下拉框**选择特定学校（显示格式："学校名（编号）"），也可选择「全部学校」。
2. 在**搜索框**中输入姓名、用户名或学科关键词，列表实时过滤（前端过滤，大小写不敏感）。
3. 两个筛选条件可组合使用：先选学校缩小范围，再输入关键词精确查找。

### 6.3 导出 CSV

**操作步骤**：

1. 根据需要设置筛选条件。未设置筛选条件则导出全部教师。
2. 点击右上角「导出 CSV」按钮。
3. 浏览器自动下载 CSV 文件，文件名格式为 `teachers-export-YYYY-MM-DD.csv`（使用当前日期）。
4. CSV 文件以 UTF-8 BOM 编码（`\ufeff` 前缀），确保 Excel 打开时中文不乱码。
5. CSV 包含以下列：学校、学校编号、姓名、用户名、学科、手机号、启用（是/否）。

### 6.4 关于教师增删改

> **注意**：超管对教师管理是**只读**的。教师的创建、编辑、删除、批量导入等操作由各学校的**学校管理员**在 `/school-admin/teachers` 页面中完成。超管可查看全平台教师数据并导出 CSV，但日常的教师管理职责归属学校管理员。这样设计是为了明确角色分工，避免超管误操作影响学校数据。

### 6.5 分页浏览

- 每页固定 50 条，通过 `skip` / `take` 参数控制。
- 使用上一页/下一页按钮翻页，显示"第 X/Y 页"信息。
- 后端接口最大返回 500 条（`MAX_TAKE=500`）。

## 7. 学生管理

路径：`/super/students`

超管以只读视角查看全平台所有学生信息，支持按学校、班级两级筛选，关键词搜索，以及导出 CSV 文件。

### 7.1 页面布局

- **顶部**：页面标题「学生管理（超管）」+「导出 CSV」按钮
- **筛选栏**：学校下拉筛选、班级下拉筛选（依赖学校选择）、关键词搜索框（姓名/学号）、学生总数统计
- **学生列表表格**：学校、班级、姓名、学号、性别、手机号、家长姓名
- **底部分页栏**：每页 50 条

### 7.2 筛选学生

**操作步骤**：

1. 先选择**学校**：下拉框列出全部学校。选择学校后，班级下拉框自动加载该校的班级列表（通过 `/api/admin/classes?schoolId=xxx` 接口）。
2. 选择**班级**（可选）：从已加载的班级列表中选择。如果未选学校，班级下拉框显示"请先选择学校"。
3. 在**搜索框**中输入姓名或学号关键词（匹配 `name`、`studentNo`、`studentName` 字段）。
4. 三个筛选条件可组合使用。

### 7.3 导出 CSV

**操作步骤**：

1. 根据需要设置筛选条件。
2. 点击右上角「导出 CSV」按钮。
3. 浏览器自动下载 CSV 文件，文件名格式为 `students-export-YYYY-MM-DD.csv`。
4. CSV 包含以下列：学校、班级、姓名、学号、性别、手机号、家长姓名、家长电话。

### 7.4 关于学生增删改

> **注意**：与教师管理相同，学生的创建、编辑、删除、批量导入等操作由各学校的**学校管理员**完成。超管仅提供只读查看与导出能力。超管可通过审计日志追踪学生的批量导入（`batch_create_students`）等操作记录。

### 7.5 级联筛选逻辑

- 切换学校时：自动清空班级筛选、重置页码、重新加载班级列表和学生列表。
- 切换班级时：自动重置页码、重新加载学生列表。
- 搜索框为前端实时过滤，不触发额外 API 请求。

## 8. 审计日志

路径：`/super/audit-logs`

审计日志记录全平台所有关键操作，是平台安全与合规审计的核心工具。日志自动记录且不可删除。

### 8.1 页面布局

- **顶部**：页面标题「审计日志」
- **筛选栏**：学校下拉筛选（含全部学校选项）、总条数统计
- **日志列表表格**：时间、操作人、动作、目标、详情
- **底部分页栏**：每页 50 条

### 8.2 筛选与查看

**操作步骤**：

1. 通过**学校下拉框**选择特定学校的日志，也可选择「全部学校」查看全平台日志。
2. 切换学校后，列表自动刷新（页码重置为第 1 页）。
3. 日志按创建时间倒序排列。
4. 使用「上一页」「下一页」按钮翻页浏览（基于 `skip` 偏移量）。

### 8.3 记录的操作类型（完整列表）

## 13. 清除业务数据

路径：`/super/account-clear`

**危险操作区**，用于一键清除全平台业务数据，保留基础演示数据。

### 13.1 页面布局

- 顶部：红色危险区标题「清除业务数据」+ 垃圾桶图标
- 红色警告卡片：说明文字 +「一键清除（保留演示数据）」按钮
- 确认弹窗（点击按钮后弹出）：清除范围清单、输入确认文字、「取消」和「确认清除」按钮

### 13.2 清除范围

**将清除（不可恢复）**：

- 所有考试、成绩数据
- 所有作业、考勤数据
- 所有课表数据
- 所有通知、公告数据
- 所有班级活动、班级风采数据
- 所有值日、班费数据
- 所有 AI 生成内容（教案/知识点/试卷/在线资源）
- 所有教学日志、听课记录
- 所有学生奖惩记录、成长记录、行为记录
- 所有家长联系记录

**将保留**：

- 学校信息
- 学校管理员账号
- 教师账号
- 班级结构
- 学生基础信息
- 超管账号
- 平台配置

### 13.3 操作步骤

1. 进入「清除业务数据」页面（红色警告区域）。
2. 阅读警告说明和清除范围清单。
3. 点击「一键清除（保留演示数据）」按钮。
4. 在弹出确认窗口中仔细阅读 6 条清除范围和 2 条保留范围说明。
5. 在输入框中输入「**确认清除**」（必须完全一致，区分大小写）。
6. 点击「确认清除」按钮执行（按钮在输入框内容不为「确认清除」时禁用）。
7. 操作调用 `POST /api/admin/reset-all` 接口，成功后显示提示并关闭弹窗。

> **警告**：此操作不可撤销。执行前请务必确认所有需要保留的数据已备份。

| 角色 | 路由前缀 | 数据访问范围 | 典型操作 |
|------|----------|-------------|----------|
| **超级管理员** | `/super` | 全平台所有学校和数据 | 管理学校、管理员、查看全平台数据和审计日志、配置平台参数 |
| **学校管理员** | `/school-admin` | 仅所属学校 | 管理本校教师、班级、学生、公告、功能包开关 |
| **教师** | `/teacher` | 所属学校 + 所教班级 | 管理所教班级的学生、考试、成绩、作业、考勤等 |
| **家长** | `/parent` | 本人关联的学生 | 查看自己孩子的学习数据、教材知识点、资源库 |

### 14.2 权限校验机制（三层防御）

**第一层：前端路由守卫**

- 根据用户角色限制页面访问。超管只能访问 `/super/*` 路由，校管只能访问 `/school-admin/*` 路由。
- 角色不匹配时跳转至 403 禁止访问页面。
- 教师路由还支持功能权限（`meta.feature`）校验，基于学校功能包控制菜单显隐。

**第二层：后端 `@Roles` 守卫**

- 所有 API 请求在服务端通过 JWT 令牌（`t.sub`）中的角色信息进行二次校验。
- 即使前端路由被绕过或 local storage 被篡改，后端仍会强制拦截越权请求。
- API 请求层在收到 401 响应时自动清除本地登录态并跳转登录页。

**第三层：后端 `@Feature` 守卫**

- 学校功能包开关由超管配置后，后端在相应 API 上校验当前学校是否开启了对应功能。
- 未开启的功能返回 403，错误消息格式：「当前功能未开放：<key>」。
- 超管与学校管理员不受此限制。

### 14.3 数据归属过滤

- 查询数据时，后端自动根据当前用户的 `schoolId`（从 JWT 令牌中提取）进行 WHERE 过滤。
- 学校管理员只能看到本校的教师、班级、学生、成绩等数据。
- 教师只能看到本校且所教班级的数据。

### 14.4 超管特例

- 超管的 API 请求**不经过** `schoolId` 过滤，可以看到全平台数据。
- 超管的审计操作（如删除学校、停用管理员、修改平台配置等）会被完整记录在审计日志中。
- 平台配置和 AI 服务商管理为超管**专有功能**，其他角色不可见也不可访问。

### 14.5 本地存储安全说明

- `localStorage` 中的 `role` / `features` 仅用于 UX 层跳转与菜单显隐。
- 真正的数据权限由后端 `@Roles` + JWT（`t.sub`）强制校验。
- 本地篡改角色信息无法越权读取数据，因为每个 API 请求都携带 JWT 令牌进行服务端身份验证。
- API 层在收到 401 响应时清除本地登录态并跳转登录，形成闭环防御。

## 15. 常见问题 FAQ

### Q1：超管可以给学校管理员批量重置密码吗？

不可以一键批量操作。超管需要逐个进入校管理员管理页面（`/super/admins`），对每个管理员单独点击钥匙图标，在弹窗中设置新密码。系统默认重置密码为 `1314520`，也可在弹窗中输入自定义密码。

### Q2：删除学校后还能恢复吗？

不能。删除学校操作不可恢复。删除前系统会弹出确认对话框提示"此操作不可恢复"，请务必确认后再操作。如果只是想暂停某学校的服务，建议使用「停用」功能而非删除。停用的学校及其所有数据会完整保留，后续可随时重新启用。

### Q3：为什么我在超管页面看不到新增教师/学生的按钮？

超管对教师和学生的管理是**只读**的。教师的创建、编辑、删除、批量导入等操作由各学校的**学校管理员**在 `/school-admin` 下完成。超管可以查看和导出全平台教师和学生数据，但日常管理职责归属学校管理员。这样设计是为了明确角色职责分工，避免超管误操作影响学校数据。

### Q4：修改平台配置后多久生效？

平台配置保存后**即时生效**。新配置通过 `PUT /api/admin/platform-config` 接口提交后立即写入数据库，后续所有 API 调用都会读取最新配置。例如修改 AI 服务商或模型后，教师下一次使用 AI 功能时即使用新配置。但已建立的连接或正在进行的 AI 对话可能不会立即切换，建议在非高峰时段进行配置变更。

### Q5：审计日志能保存多久？可以导出吗？

审计日志根据后端数据库存储策略决定保留时长，系统目前不主动删除历史日志。超管可通过学校筛选和分页浏览所有历史记录。当前版本暂不支持审计日志的 CSV 导出功能，但可通过浏览器查看所有日志详情。

### Q6：学校功能包关闭后，学校管理员还能使用该功能吗？

**可以**。学校功能包开关仅影响该学校的**教师**和**家长**角色。超管和学校管理员不受学校功能包限制，始终拥有全部功能。这是因为超管和学校管理员属于管理角色，需要完整的系统管理能力。

### Q7：AI 服务商的 API Key 是存储在哪里的？

平台级别的 API Key（在「平台配置」>「AI 配置」中设置）加密存储在服务端数据库中。在「AI 服务商管理」中维护的服务商清单**不存储 API Key**，仅包含服务商名称、接口地址和模型列表。教师和学校管理员如需使用特定服务商，需在个人设置中自行录入自己的 API Key，平台不会收集或存储用户个人的 API Key。

### Q8：成绩审计中的汇总数据是实时计算的吗？

是的。成绩审计页面的学科汇总分析数据是实时从数据库中的成绩表聚合计算得出的，反映当前最新的成绩数据状态。考试列表和成绩列表也直接从数据库查询，每次点击「刷新」按钮都会重新请求最新数据。如果数据量较大，查询可能需要一些时间，页面会显示加载动画。

### Q9：超管可以修改自己的密码吗？

超管密码由后端环境变量（`SUPER_ADMIN_USER` / `SUPER_ADMIN_PASSWORD`）配置，不通过前端页面修改。如需修改超管密码，请联系系统运维人员在服务器端更新环境变量或 `.env` 文件中的配置，然后重启服务。

### Q10：清除业务数据后，教师的账号还在吗？

教师的账号信息会**保留**。"清除业务数据"功能只清除业务数据（考试、成绩、作业、考勤、通知等），不会删除学校、管理员、教师、班级、学生等基础账号和结构数据。如需彻底删除教师账号，请联系对应学校的学校管理员在 `/school-admin/teachers` 中操作。
